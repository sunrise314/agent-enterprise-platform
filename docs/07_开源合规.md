# 07 开源合规

> 基于 AgentScope-Java（Apache 2.0）二次开发并对外交付源码时的法律与合规要求。

## 7.1 AgentScope-Java 许可（Apache 2.0）

Apache 2.0 允许：
- ✅ Fork、修改、二次开发
- ✅ 商业化，将衍生产品（源码包 / 软件许可）出售给企业客户
- ✅ 闭源交付（保留原项目部分必须遵守义务）
- ✅ 不强制开源你新增的自研业务代码，不需向版权方付费

## 7.2 必须遵守的硬性义务（保留原项目源码时）

1. **附带许可证**：交付源码包时，必须包含 Apache-2.0 协议文本
2. **修改标注**：修改过的原项目文件，文件头加注释声明「本文件已被我方修改」
3. **保留声明**：保留原有全部版权、NOTICE、作者声明，不得删除阿里版权注释
4. **禁止冒名**：不得暗示产品为阿里官方出品，不得冒用商标

> 简单理解：Apache 2.0 免费授权的是「框架底座」，你卖的是「基于底座开发的整套 AI 应用产品 + 实施服务」，不是单纯转卖 AgentScope-Java 源码。

## 7.3 商业模式边界

- ❌ **不建议**：只售卖 AgentScope-Java 原生源码——客户可到 GitHub 免费下载，无商业价值
- ✅ **正确**：售卖「自研业务层 + 底座」打包的完整企业 Agent 平台（RAG / 评估 / 权限 / 管理 API 是你的核心增值）

## 7.4 依赖链审计（重要风险）

- 审计全部第三方依赖的开源协议
- 避免引入 **GPL / AGPL 等强传染协议**，否则可能污染你的闭源代码，强制开源
- 重点关注：模型 SDK、向量库客户端、文档解析库、Spring 依赖

**审计流程：**
```
mvn dependency:tree           # 列出全部依赖
核对每个依赖的 License
标记传染性协议（GPL/AGPL/MPL）
不满足 → 替换为兼容协议替代库
生成依赖清单（交付客户）
```

## 7.5 交付源码给企业（合规文案示例）

```
底层智能体框架：AgentScope-Java（Apache 2.0）
  上游地址：https://github.com/agentscope-ai/agentscope-java
  保留原版权声明与 NOTICE。
上层业务应用：我方自研闭源软件（biz-platform），版权归我方所有。
第三方依赖清单：见 DEPENDENCIES.md
```

## 7.6 专利条款说明

- Apache 2.0 自带专利授权条款
- 高敏感政企项目建议做开源合规审计 + 法务复核
- 明确产品责任边界：交付整套系统，**我方对整套产品稳定性与业务 bug 负责**，原版权方不承担产品质保
