## 11.2 前置：统一登录拿 Token（所有业务接口前置）

```bash
# admin / employee 两个角色账号，返回 role + permissions + Bearer token
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
# → code=0, role=ADMIN, permissions=[kb:index,audit:view,agent:chat,eval:run,agent:manage], token=eyJ...
```

所有后续接口带 `Authorization: Bearer <token>`。

## 11.3 各项能力明细

### ① 对话执行链路（AgentServiceImpl）
- **复现**：`curl -X POST http://localhost:8080/api/agent/chat -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"query":"你好","sessionKey":"s-1"}'`
- **量化**：`latencyMs=2768, tokenIn=888, tokenOut=89`（真实 DeepSeek 用量）
- **证据**：`biz-platform-run.log`（AUDIT 行含 cost=2768ms）
- **面试**：对话不止是「调 LLM」，要能拆出 token 成本与延迟的逐项来源。

### ② 会话持久化（ChatMemory：InMemory/Redis，按 profile 切换）
- **复现**：轮 1 问「我叫张伟」；轮 2 问「我叫什么」
- **量化**：跨轮记忆命中（demo=内存，prod=Redis `@Profile("!demo & !milvus")`）
- **面试**：多轮上下文 = 显式 memory 而非拼 prompt；生产用 Redis TTL（`ttl-seconds=86400`）防膨胀。

### ③ RAG 文档问答（ApplicationLayerRagExample 模式）
- **复现**：问「公司年假政策？满几年休几天？」
- **量化**：`kb_search` 命中【员工手册】，正确作答 满1年5天/满10年10天/满20年15天
- **面试**：RAG 不是把整库塞进 prompt，而是「检索→格式化→工具交给 Agent→基于上下文作答」四步。

### ④ Milvus 实机向量检索（MilvusHybridRetriever + OpenAiEmbeddingService）
- **复现**：
  1. `curl -F "file=@员工手册.txt" -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/kb/ingest`
  2. `curl -X POST .../api/agent/chat -d '{"query":"员工一年可以休几天年假？"}'`
- **量化**：ingest `indexed=2, chunkSize=488`；chat 语义召回年假 chunk 正确作答；tokenIn=888/out=89/2768ms
- **栈**：bge-small-zh-v1.5（512 维，ModelScope 下载本地加载）+ Milvus v2.4.12 + `kb_{tenantId}` collection + COSINE + RRF
- **证据**：`docs/03_模块设计/03_02_rag_module.md` 3.2.12
- **面试**：向量检索查的不是字面，是语义；混合检索（向量+BM25）+ RRF 重排补精确术语召回。

### ⑤ 评估 Runner（EvalRunService + EvalCase/EvalJudge 三断言）
- **复现**：`POST /api/eval/run`
- **量化**：初版 2/5 过 → 修断言稳健性 → **5/5 全绿**
- **证据**：`src/biz-platform/src/main/resources/eval/eval-cases.json`（6 用例含对抗）
- **面试**：断言三模式（contains/not_contains/数值）覆盖「答没答、答对没、答偏没」。

### ⑥ LLM-as-judge（LlmJudge）
- **复现**：跑评估，观察 judge 输出 `{score,hallucination,comment}`
- **量化**：用例 p-002 断言过但 judge 识别「编造差旅标准」打分 4（rule 断言与 judge 互补）
- **面试**：规则断言 + LLM judge 双轨；judge 能抓「答得流畅但事实编造」。

### ⑦ JWT 认证 + RBAC（JwtUtil + AuthInterceptor）
- **复现**：三个 token 分别打受保护接口
  - admin/admin123 → ADMIN → **200**
  - employee/pass123 → EMPLOYEE → **403**（打 /api/eval）
  - 篡改/过期 token → **401**
- **量化**：路径→权限映射（/api/agent→agent:chat、/api/eval→eval:run、/api/audit→audit:view）
- **面试**：认证（你是谁）与授权（你能干啥）分离；JWT HS 签名 + 过期校验。

### ⑧ 多租户隔离（TenantInterceptor → RuntimeContext 链路注入）
- **复现**：tenant-0 上传文档，tenant-1 提问
- **量化**：tenant-0 命中 / **tenant-1 隔离不泄露**
- **坑**：Reactor boundedElastic 线程 ThreadLocal 读不到 → 改用 `RuntimeContext.put(TenantInfo)` 随链路注入（非 @ToolParam）
- **面试**：多租户隔离 = 数据不能串；纯 ThreadLocal 在异步线程失效，要随链路传播上下文。

### ⑨ 审计日志（AuditLogger 埋点）
- **复现**：任意 agent.chat / tool.kb_search 后 `GET /api/audit`
- **量化**：`AUDIT tenant=tenant-0 user=1 action=agent.chat success=true cost=2768ms detail=q=...`
- **面试**：审计是「留痕可追溯」，埋点选关键动作 + 成本/耗时维度。

### ⑩ token 真实采集（Msg.getUsage → ChatUsage）
- **复现**：chat 响应 metrics.tokenIn/tokenOut
- **量化**：真值 `tok=612/108`（来自模型响应 usage，非估算）
- **面试**：token 计费必须取模型返回的真实 usage；这是成本审计的基础。

### ⑪ SSE 流式对话（AgentServiceImpl.streamEvents → Flux<AgentEvent>）
- **复现**：`POST /api/agent/chat/stream`
- **量化**：事件流 `delta=122 / tool=1 / done=1`（文本增量+工具调用+完成三类事件）
- **证据**：getter 已核：`TextBlockDeltaEvent.getDelta()` / `ToolCallStartEvent.getToolCallName()` / `AgentResultEvent.getResult()`
- **面试**：流式 = 首 token 延迟优化 + 工具调用过程可视化；事件驱动而非轮询。

### ⑫ 文档解析 + 语义分块（DocumentParser + SemanticChunker）
- **复现**：上传 PDF/DOCX/TXT
- **量化**：员工手册分块 2 chunks；外包制度短文档合并 1 块；超长段按句子边界二次切带 overlap
- **栈**：PDFBox 2.0.31 + poi-ooxml 5.2.5
- **面试**：语义分块（段落感知）比固定窗口更适合制度/合同，避免切碎条款。

### ⑬ Query 改写（QueryRewriter）
- **复现**：问「我们公司请假咋算的呀，能休几天？」
- **量化**：改写为「请假流程 申请 审批」（日志 `[query-rewriter]`）→ 正确召回年假规定
- **面试**：口语→检索友好 query；失败兜底原 query；可配缓存/仅短 query 触发控成本。

### ⑭ 指标入库（MetricsStore + MetricsSubscriber 旁路订阅）
- **复现**：`GET /api/metrics/summary`、`GET /api/metrics/series`
- **量化**：`calls=1, tokenIn=934, tokenOut=145, p95=5104ms`
- **架构**：订阅 `AgentEventPublisher` 旁路，不侵入主链路
- **面试**：可观测性走事件订阅，与业务解耦；分钟级聚合。

### ⑮ 坏例自动沉淀（BadCaseRepository）
- **复现**：对抗用例 **a-002**（问食堂菜单，`forbidden=["菜单","菜品","周一到周五"], assertion=not_contains`）
- **量化**：Agent 编造被命中 → fail → 落盘 `testcases/bad-cases.json`（halluc=True）
- **面试**：把「错的样本」沉淀进测试集，形成回归闭环，防再次编造。

### ⑯ 增量 ingestion（DocVersionTracker + removeByTitle）
- **复现**：首次上传 → 重复上传 → 修改后上传
- **量化**：`indexed=1/skipped=false` → `indexed=0/skipped=true`(去重) → `indexed=1`(更新)
- **面试**：SHA-256 内容哈希比标题比对精确：标题不变内容微调也能识别变化。

## 11.4 面试话术总纲（30 秒版）

> 「我基于 AgentScope-Java 二次开发了一套企业级智能体平台，走 **少侵入、SPI 扩展** 路线。全部功能不是 demo，是**实机验证过的闭环**：对话、多轮记忆、RAG（含 Milvus 真实向量检索）、自动评估（5/5 通过 + LLM-judge 抓幻觉）、JWT+RBAC 权限、多租户隔离、审计、token 真实计费、SSE 流式、指标可观测、坏例回归、增量入库。核心亮点是**每项都有量化指标**——token 成本、延迟 p95、检索命中率、评估通过率、权限矩阵、审计留痕——面试官可以任选一条链路深挖到代码级。」
