# 12 复盘：离商用还差什么

> 第十二章是连载收官。这一章不吹完成度，把所有还在 demo 态的地方摊开讲：哪些是架构上已经铺好只差工程收口，哪些是真要重做的。

## 先给一个诚实的锚点

目前 16 项核心能力全部实机验证通过。但「全部验证通过」和「可商用交付」之间还有一道明确的工程鸿沟。这一章逐条列出来，按修复优先级排序。

## 差距清单（按优先级）

### P0：必须收口才能交付

| # | 差距 | 现状 | 修复方案 | 修复量 |
|---|---|---|---|---|
| 1 | **零单元测试** | `biz-platform/src/test` 目录不存在 | 补 `@SpringBootTest` 集成测试 + 核心类 JUnit5 单元测试，覆盖率 ≥ 60% | 大 |
| 2 | **审计日志内存环形缓冲** | 仅保留 2000 条，重启即丢 | 升级为 PostgreSQL 落库，加归档策略（热数据 30 天 + 冷数据 1 年） | 中 |
| 3 | **指标内存存储** | `InMemoryMetricsStore` 单机态，多实例裂 | 换 Micrometer + Prometheus 远程写，或 InfluxDB | 中 |
| 4 | **H2 演示态 + ddl-auto: update** | demo profile 用 H2 内存，生产 PostgreSQL 无 Flyway | 补 Flyway 迁移脚本，`ddl-auto: validate` | 小 |
| 5 | **SQL 沙箱 Guard 不够强** | 正则拦截 DDL/DML，但可被注释绕过 | 换 Apache Calcite 做语法解析 + Row Level Security 强制 | 大 |

### P1：商用体验必须补

| # | 差距 | 现状 | 修复方案 |
|---|---|---|---|
| 6 | **BM25 内存索引与向量库脱节** | `docIndex` 是 `ConcurrentHashMap`，重启后和 Milvus 不同步 | 生产换 OpenSearch 原生 BM25，索引落盘、支持分布式 |
| 7 | **不可水平扩展** | 审计/指标/会话全单机内存态 | Redis 做会话 + 指标缓存，OpenSearch 做审计落库，K8s HPA |
| 8 | **无压测数据** | 没跑过压测，SLA 全是估算 | JMeter 压测 100 并发，记录 p95、错误率、token 成本 |
| 9 | **SSE 无断线重连** | 网络抖动后 SSE 连接断开，用户要重发请求 | 加客户端 ID + 事件序号，断线后从断点续传 |

### P2：锦上添花

| # | 差距 | 现状 | 修复方案 |
|---|---|---|---|
| 10 | **评估结果无可视化** | 评估结果只落 JSON | 接 Grafana Dashboard 或自建简单评估面板 |
| 11 | **无限流熔断** | Agent 无调用频率限制，可能无限循环调工具 | 加 Bucket4j 限流 + Resilience4j 熔断 |
| 12 | **Prompt 注入防护弱** | 只有简单关键词过滤 | 加 PromptGuard 或在 Agent Guard 层做输入分类 |

## 架构上已经铺好的路

好消息是：**上面 12 条里，有 8 条不需要改业务代码，只需要换实现**。原因是我从一开始就用接口先行 + Profile 切换：

- `Retriever` 接口：`MilvusHybridRetriever`（内存 BM25）→ 换 `OpenSearchHybridRetriever`（原生 BM25），上层 RagService 零改动；
- `ChatMemory` 接口：`InMemoryChatMemory`（demo）→ `RedisChatMemory`（prod），切换靠 Profile；
- `MetricsStore` 接口：`InMemoryMetricsStore` → 换 Prometheus 远程写实现；
- `AuditLogger`：环形缓冲 → 落 PostgreSQL，调用方零改动。

这就是前一章讲的「接口先行 + Profile 切换」的价值——**架构上已经铺好路，差的是把 Profile 从 demo 切到 prod，再把每个接口的生产实现补完**。

## 一句话收尾

这个项目目前是 **「架构商用级、完成度 MVP 级」**：16 项核心能力实机验证、旁路架构零侵入、双态 Profile 可切换、租户隔离/审计/评估/成本闭环全部跑通。但工程收口还有 12 条差距——零测试、审计内存态、SQL Guard 不够强是最优先要补的。下一步就是把 P0 的 5 条补完，P1 的 4 条跟上，P2 的选做，就能到「可私有化交付」的商用级。
