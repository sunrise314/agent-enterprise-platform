# 10 评估闭环：双轨断言与坏例回归

> 第十篇进评估。这一章是面试最容易露馅的地方——功能跑通谁都会，但说得清指标、拿得出数据、形成得了闭环的，没几个。

## 为什么单轨不够

最开始我只做了规则断言：`contains` 判答没答、`not_contains` 判答偏没。跑起来发现一个问题：有个用例规则断言全过，但 Agent 回答里编造了「差旅标准 1000 元/天」——知识库里根本没有这条。规则断言只查关键词对不对，查不出来「编得像真的但无依据」的情况。

所以必须双轨：**规则断言兜底精确匹配 + LLM-as-judge 补语义幻觉检测**。

## 双轨断言设计

规则断言三种模式：

```json
{
  "question": "员工年假怎么计算？",
  "expectedKeywords": ["年假", "工龄", "10年", "20年"],
  "forbiddenKeywords": ["虚构", "编造"],
  "expectedNumeric": null
}
```

| 模式 | 判定逻辑 |
|---|---|
| `contains` | 回答必须包含 expectedKeywords 里的全部词 |
| `not_contains` | 回答不能包含 forbiddenKeywords 里的任何词 |
| 数值 | 回答里的数值必须等于 expectedNumeric |

LLM-as-judge 是 `LlmJudge.java`，设计要点：

1. **固定 judge 模型 + 固定 prompt**：和主 Agent 用同一个模型，prompt 里明确要求输出 JSON `{score, hallucination, comment}`；
2. **judge 不生成答案，只打分**：它收到问题、期望/禁用关键词、Agent 回答，只做评判不做推理；
3. **judge 结果作相对参考，不作为绝对真值**：不同时间跑 judge 可能有波动，但相对对比有意义；
4. **judge 上下文独立**：userId/sessionId 都设成 "judge"，和主对话彻底隔离。

```java
private static final String JUDGE_PROMPT = """
        你是严格的 Agent 回答评估裁判。
        请根据【问题】和【期望/禁用关键词】判断【回答】是否满足要求。
        只输出 JSON：{"score": <1-5>, "hallucination": <true/false>, "comment": "<一句话>"}
        """;
```

## 坏例自动沉淀

评估跑完，所有 fail 的用例（规则断言没过 OR judge 打分 < 3 OR 标记 hallucination）自动落盘进 `bad-cases.json`：

```java
// EvalRunService 评估结束后
if (!rulePassed || judge.score() < 3 || judge.hallucination()) {
    badCaseRepo.add(failedCase, agentAnswer, judge.comment());
}
```

坏例集和测试集分开存：

- `eval-cases.json`：固定测试集，每次评估都跑；
- `bad-cases.json`：动态增长的回归集，改 prompt/换模型后先跑坏例回归。

## 实测数据

- 评估通过率：初版 5 个用例只过 2 个，修断言稳健性后 5/5；
- LLM-as-judge：抓出 1 个规则断言漏掉的编造案例（「差旅标准 1000 元/天」无依据）；
- 坏例沉淀：1 条对抗用例（故意问知识库里没有的食堂菜单）被自动标记幻觉、落盘；
- token 成本：一次完整评估（5 个用例 + 5 个 judge）≈ 6200 token，约 ¥0.02。

## 一句诚实的收尾

这套评估框架和 LangSmith 在 SaaS 里做的事等价——Datasets + Experiments + Evals，但我是自研的。约束是 Java 技术栈 + 私有化交付，LangSmith 的 Python SDK 接不进来，Langfuse 的 OTLP 理论上可接但 judge prompt 要业务定制。自研的代价是没有现成的可视化界面，评估结果目前只落 JSON，下一步接 Grafana 或自建简单 Dashboard。
