# 04 数据模型

> 核心表设计，覆盖业务、会话、知识库、评估、审计。数据库：PostgreSQL + Redis。

## 4.1 PostgreSQL 核心表

### 4.1.1 租户 / 用户 / 权限

**tenant（租户）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | |
| name | VARCHAR(128) | 租户名 |
| status | SMALLINT | 1 启用 0 停用 |
| created_at | TIMESTAMP | |

**sys_user（用户）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | |
| tenant_id | BIGINT FK | 所属租户 |
| username | VARCHAR(64) | 登录名 |
| password_hash | VARCHAR(128) | 密码哈希 |
| display_name | VARCHAR(64) | 显示名 |
| status | SMALLINT | |

**role（角色）/ user_role（用户角色）/ role_permission（角色权限）**
标准 RBAC 三表，权限为「资源 + 操作」粒度。

## 4.2 Redis 存储

| Key | 类型 | 说明 |
|---|---|---|
| `session:{tenant}:{key}` | Hash | 会话消息流 |
| `ratelimit:{tenant}:{user}` | ZSet | 滑动窗口限流计数 |
| `eval:lock:{runId}` | String | 评估批次锁 |
| `trace:{traceId}` | String | 链路缓存（可选） |

## 4.3 Milvus

- Collection：`kb_chunk_vec`
- 字段：`id`、`tenant_id`、`doc_id`、`vector`（embedding）、`metadata`
- 查询：向量检索 + `tenant_id == ?` 过滤 + TopK

## 4.4 建表规范

- 所有业务表带 `tenant_id`，强制租户隔离
- 审计日志只追加、不 UPDATE
- 时间字段统一 `TIMESTAMP`
- 敏感字段脱敏存储，不落明文（密码哈希）
