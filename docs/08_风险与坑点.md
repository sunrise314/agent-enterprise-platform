# 08 风险与坑点

> 项目开发与上线过程中的踩坑清单，也是面试高频「你遇到什么坑」的答题素材。

## 8.1 Agent 编排类

| 坑点 | 现象 | 解决方案 |
|---|---|---|
| Agent 死循环 | 反复调用工具不收敛 | AgentGuard 最大轮次限制（默认 8）+ 总超时 |
| 状态污染 | 多会话共享 Agent 状态 | 每会话独立 RuntimeContext + Redis 会话隔离 |
| 工具选错 | LLM 调用错误工具 | 工具 description 写清用途；结果回传自纠；统计准确率 |
| 上下文膨胀 | 长会话 token 超限 | HarnessAgent 上下文压缩 / 裁剪策略 |
| 中断续跑 | 任务中断后状态丢失 | Checkpoint 持久化会话 State 到 Redis |

## 8.2 RAG 类

| 坑点 | 现象 | 解决方案 |
|---|---|---|
| 分块不合理 | 召回碎片化 / 信息断裂 | 结构文档语义分块 + 标题层级；大文档固定块 + overlap |
| 纯向量召回差 | 精确术语 / 编号检索不到 | 混合检索（向量 + BM25）+ RRF 重排 |
| 幻觉 | 输出无原文支撑 | 检索片段带来源元数据，judge 校验幻觉率 |
| 表格解析失败 | 表格内容丢失 | 专用表格解析（PDFBox + 表格识别） |
| Query 歧义 | 检索不到正确内容 | Query 改写 / 扩写 + 引用溯源 |

## 8.3 工程稳定性类

| 坑点 | 现象 | 解决方案 |
|---|---|---|
| LLM 超时 | 请求挂起 | 超时控制 + 重试（指数退避） |
| 并发打爆模型 | 限流 / 配额超限 | LLM 侧限流 + 熔断 |
| Prompt 注入 | 诱导越权 / 忽略规则 | 输入过滤 + 系统提示词强约束 + 检索内容隔离 |
| SQL 工具风险 | 删改数据 | 只读白名单 + 单语句 + 超时 + LIMIT + 脱敏 + 审计 |
| 会话状态丢失 | 用户重连无记忆 | Redis 持久化，Agent 实例无状态化 |

## 8.4 评估类

| 坑点 | 现象 | 解决方案 |
|---|---|---|
| LLM-judge 偏见 | 打分不稳定 | 固定 judge 模型 + prompt；关键 case 人工复核 |
| 判定模糊 | 任务成功标准不清 | 定义 Success Predicate，缺一即失败 |
| 测试集不固定 | 迭代无法对比 | 固定测试集基线 + 每次迭代跑同一套 |
| 评估侵入主链路 | 影响线上性能 | 旁路异步采集，不阻塞主链路 |

## 8.5 合规 / 部署类

| 坑点 | 现象 | 解决方案 |
|---|---|---|
| 传染性依赖 | 引入 GPL 污染 | 依赖树审计 |
| 内网无外网模型 | 无法调用 API | 私有化模型（Ollama / vLLM）+ 配置外置 |
| 内存不足 | Milvus / 服务 OOM | 资源配额 + 缩 index 参数 |
| 端口冲突 | 容器起不来 | docker ps 检查 + 改映射 |

## 8.6 面试总结话术

> 答：这个项目最大的难点，一是 Agent 多轮工具调用的状态管理与防死循环，我用最大轮次 + 超时 + 独立会话上下文解决；二是效果评估，我建了固定测试集和量化指标，用 LLM-as-judge 粗筛 + 人工复核，沉淀 bad case 回归；三是工程稳定性，做了限流、熔断、Prompt 注入防护、SQL 沙箱和私有化部署。这些都是普通 Demo 没有的。
